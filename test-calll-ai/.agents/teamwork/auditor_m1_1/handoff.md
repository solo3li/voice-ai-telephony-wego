## 3. Caveats

1. **Cross-Timezone Input in `is_operating_hours`**: In `test_m1_challenger_stress.py`, when a timezone-aware `datetime` object in UTC is explicitly passed into `is_operating_hours(user_id, dt=dt_utc)`, the underlying schedule logic compares the time component directly without converting `dt.astimezone(tz)`. In normal production operation, `dt` is `None` and the system evaluates `datetime.now(tz)` in Cairo time directly, so this does not affect default behavior. It is recommended for Milestone 2 to normalize `now_dt = now_dt.astimezone(tz)` if `dt` is timezone-aware.
2. **Presence Status Casing Variance**: `AgentPresence.is_available()` evaluates lowercase, titlecase, and uppercase variants, whereas the SQL filter in `get_available_agents` specifies `status__in=['ready', 'AVAILABLE', 'available', 'Ready']`. Uppercase `'READY'` is not in the SQL list. In production, statuses are set to `'ready'` or `'AVAILABLE'`.
3. Neither of the above caveats represents an integrity violation or facade implementation.
